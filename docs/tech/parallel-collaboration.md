# 四岗位协作：范围调度、可靠交接、证据验收

## 目标与边界

让固定的老板、技术、研发、运营按独立子任务并行工作，避免同目录全局锁造成无谓等待；交付前收集结构化证据并完成独立复核。保留现有模型、会话 ID、历史、项目目录、完整执行能力及只读方案模式。不新增工作台以外的代理、不改模型、不自动发布、不打断正在运行的服务。

## 方案取舍

1. 仅改提示词：成本低，但无法解决调度器把所有同目录任务串行化的问题。
2. **声明读写范围 + 版本化工作单 + 消息收件箱（采用）**：兼容非 Git 项目，独立范围可并行，重叠的写入/读取等待。保留现有会话及工具接口，新增可选字段和共享交付工具。
3. 每人独立 Git worktree：隔离更强，但本项目不是 Git 仓库，任意用户目录也未必有 Git；合并、依赖和产物路径成本高。本次不引入。

## 领域模型与数据流

- `workItems`：每次分工形成不可混淆的工作单 ID，关联固定成员、任务、读写范围、验收条件、依赖工作单、复核目标、状态与交付报告。后续重做可显式替代同成员的旧工作单；历史仍保留。
- 范围由 `readPaths` / `writePaths` 两组项目相对路径组成；空写列表表示本次只读。未声明范围沿用保守的全目录锁。写写、写读存在父子路径交集时等待，纯读取互不阻塞。
- 调度仍保留全局 6 个会话、最多 2 个老板，每个目标最多 3 个执行成员。老板在同事执行期间负责沟通、决策和证据检查，不同时写共享目录。
- 消息先持久化，活动会话尽力实时投递；未启动、已结束、初始化中或实时投递失败时留在收件箱。成员下一轮启动自动带入未交接消息，工具可主动读取。消息本身不擅自唤醒成员。
- `office_report`：记录结论、成果路径、检查项及证据、风险；复核工作绑定指定工作单，作者不能自审。相关文件在复核后再次被写入时，该复核失效，必须重新检查。
- 协作目标最终交付要求所有有效工作单结束、报告及检查通过，所有写入工作有独立通过的复核；未满足时向老板反馈缺项，最多追加 2 轮质量补全，仍不满足则明确 `needs_attention`，不显示已交付。

## 模块

- `server/collaboration.js`：范围规范化、冲突判定、工作单与证据规则。
- `server/missions.js`：调度、消息交接、工作单生命周期、质量补全与持久化。
- `server/prompts.js`：分工/继续接口扩展，共享收件箱与报告工具，以及并行执行与验收的岗位协定。
- `src/collaboration-panel.js`：工作计划页的协作分工、范围、报告及验收缺项；沿用现有消息和执行记录。

## 关键限制与安全

范围是调度与岗位协定，不是操作系统级沙箱。完整执行权限保持不变；明确检测到的越界文件事件将记入工作单并阻止验收，但命令或外部工具的所有副作用无法由声明范围强制隔离。符号链接和目录穿越在范围校验中拒绝越出项目，未声明范围不乐观并行。最终质量门检查报告结构、独立性和时序，并不保证模型提供的证据一定正确。

已有历史目标不补造工作单、不追溯改变已交付状态；继续后使用新工具产生的分工才纳入新规则。聊天/单人模式保持原行为。服务需在活动目标结束后重启，除非用户明确同意中断。

## 验证与回退

覆盖三人同时启动、读读并行、重叠路径串行、父子目录及符号链接、跨目标保护、依赖失败、初始化/离线消息、重复收件、停止清理、结构化报告、自审拒绝、复核过期及修复重验。运行完整测试和构建，使用隔离数据验证 UI；不启动真实收费模型来做测试。

回退到未声明范围时即恢复全目录保守调度；新字段为附加字段，不删除原消息、代理或文件。旧版本读取数据时不应把新增报告当成模型真实执行的替代证据。

## 会话工具兼容性核验

[OpenAI App Server 官方文档](https://learn.chatgpt.com/docs/app-server)说明动态工具会随会话保存与恢复。本机安装的 Codex 0.153.4 实际生成协议中 `ThreadResumeParams` 没有替换 dynamicTools 的字段，因此不假设恢复旧会话就能更新旧工具 schema。采用按会话配置本地 office MCP 的方式提供新版工具，保留历史会话；旧动态工具仍可兼容调用，但提示模型优先使用 MCP 新版。

已在本机真实 Codex 临时会话验证：office MCP 状态 connected，列出 inbox、team、report、delegate 等 9 个工具；没有启动任何模型推理轮次。MCP 工具库存另有四岗位子进程测试，确认只有老板得到分工入口。
