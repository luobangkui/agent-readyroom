# 协作任务图：运行时拆分、回调通知与关键路径调度

## 目标与边界

在既有协作 harness（工作单、范围锁、资源预约、阶段契约、证据与独立复核）之上，把三件事做扎实：

1. **任务可以边做边拆**：执行成员发现手头工作其实是多件事时，当场拆成并行子任务，不必回到规划者等一个模型往返。
2. **成员之间可以互相回调**：关注别人的进度用订阅，不用轮询共享看板；事件发生会可靠落到收件箱，需要行动时自动唤醒。
3. **图永远无环，并且按关键路径高效派发**：每次加边都复查环，调度优先长路径而不是先来先服务。

不改动：四岗位职责与合同、独立复核与证据门槛、范围/资源锁的保守语义、模型与运行环境选择。拆分与回调都走同一条工作单流水线，不新增第二套调度。

## 运行时拆分（office_split）

- **谁能拆**：领取人本人，或目标负责人（老板）。其他成员只能看。
- **拆什么**：任务图里（protocol 2）尚未结束、未被替代、且没有拆过的工作单。拆过的父工作单不再二次拆分，但子任务本身可以继续拆。
- **子任务约束**：2–12 项；每项要自己的 key、task、eligibleRoles、scope、acceptance；`scope` 必须落在父工作单**已批准的范围之内**（拆分不放宽爆炸半径）；不能声明 `replaces`（返工属于规划者的动作）；`dependsOn`/`reviewOf` 可以指向已存在的 key/ID 或同批兄弟 key；优先级不超过父工作单；拆分深度最多 3 层。
- **父工作单变成汇总代次（join）**：`parent.dependsOn` 追加全部子任务，状态回到 `waiting_input`。子任务全部结束（且证据通过）后，父工作单重新变成 `ready`，被领取为新一代（generation+1）执行。这一代拿到子任务结果作为固定输入，必须覆盖父工作单**原来的全部验收条件**，并继续承担父工作单声明的 `produces`。下游消费者因此不需要重新指向任何节点。
- **拆分轮次的收尾**：成员是在自己的轮次里调用 office_split 的，工作单被标记 `drain`。该轮次真实结束时只记录这一次 attempt（状态 `split`），不会把父工作单算成"已完成"；席位立即释放，成员可以去领子任务。子任务在父工作单仍被占用期间不会抢跑（范围锁自然挡住），轮次结束后并行派发。
- **原子性**：子任务与新的边先在旁边构造，整图复查环与输入生产者，全部通过才落盘；保存失败整体回滚，不会留下半个扇出。
- **幂等**：`requestId` 去重；同 ID 不同任务内容会被拒绝。

## 回调通知（office_watch / office_unwatch）

成员在轮次里订阅持久化事件，然后该干什么干什么，不再 `office_team` 轮询。

- **事件**：`work.settled`（任一终态）、`work.completed`、`work.failed`、`artifact.published`、`artifact.validated`、`member.idle`。
- **目标**：工作单 key 或 ID、阶段契约 `name` 或 `name:version`、成员 ID，或 `*`。
- **投递顺序**：先写可靠收件箱并落盘，成功后才谈唤醒。中间崩溃只会丢唤醒，不会丢通知。
- **唤醒**：`wake`（默认开）时，如果订阅者当前空闲（非执行中/排队中）且没有未开始的回调工作单，调度器为它创建**一张真实工作单**（`callback-N`，优先级 6，范围沿用该成员上一张工作单），于是"对事件作出反应"也走范围锁、证据与复核规则。每成员最多 6 张回调单，同一时刻只有 1 张未开始，避免事件风暴变成刷轮次。
- **生命周期**：默认一次性触发；`repeat` 时可触发至多 5 次；`expiresInSeconds`（默认 1 小时）到期失效；`office_unwatch` 取消。重复登记同一订阅是幂等的。

## 无环保证

`src/work-graph.js` 是唯一一份 DAG 实现，服务端调度和浏览器画图共用：

- `dependencyIds` 把显式 `dependsOn` 和"阶段契约 `requires` → 生产者"两类边合并成一张图。
- `assertAcyclic` 提交任务图（`prepareGraph`）与运行时拆分（`prepareSplit`）**两处都强制执行**，发现环就带出环路链并原子拒绝。模型没有任何路径能造出环。
- `topoLayers` 给出并行批次；`criticalPath` 给出每个工作单的下游最长链。
- 手工改坏的数据（例如直接编辑 missions.json）不会被悄悄按错误顺序执行：批次排不进去的工作单会列在 `cycles` 里，面板显式提示。

## 调度效率

- **关键路径优先**：候选排序 `优先级 × 1000 + 下游最长链 × 120 + 续接奖励 + 等待时长`。同一个优先级下，别人都在等的那条链先上。
- **续接优于冷启动**：已有 attempt 的工作单（挂起后恢复）加 150 分，因为它带着检查点继续，比新开一轮便宜。
- **一次派完**：一轮调度里遍历全部就绪工作单，给每个空闲且岗位匹配的成员各派一项，不再逐人唤醒。
- **名额可配置**：`OFFICE_MAX_SESSIONS`（默认 6）、`OFFICE_MAX_WORKERS`（每目标执行成员，默认 3）、`OFFICE_MAX_BOSSES`（默认 2）。默认值与旧行为一致；确认模型配额后可以调大，调度器不需要改动。

## 视图

`src/work-graph-view.js` 在工作计划页画任务图：拓扑分批（列＝批次，标注每批可并行项数）、实线＝工作依赖、虚线＝阶段契约依赖、加粗＝关键路径；节点标出状态、领取人、拆分/子任务/复核/回调/高优先级徽标与等待原因。所有模型产出经过转义；环上的节点会画在"未排入批次（存在环）"一列。

- `test/work-graph.test.js`：分层、关键路径、替代生产者、环检测、视图渲染与转义、坏数据的环列。
- `test/split-watch.test.js`：拆分后的并行派发与汇总代次、范围放大/未知引用/环/单子任务/`replaces` 全部原子拒绝、拆分幂等与深度、订阅投递与唤醒一次、一次性与取消、事件类型校验、关键路径优先与名额限制。
- 全量 `npm test` 保持通过；`npm run build` 产出含 DAG 视图的前端。

## 限制与回退

- 拆分粒度仍由模型判断，程序只保证"不放大范围、不成环、不重复派发"；不保证拆得合理。
- 回调唤醒需要一张真实工作单，因此一次唤醒等于一个模型轮次；事件风暴由每成员限流挡住，但仍要按需订阅。
- 范围锁不是文件系统级隔离；拆分后的子任务并行仍受 `scope` 与资源预约约束。
- 回退：`office_split`/`office_watch` 是新增工具，去掉相应的 `dynamic()` 分支与提示词段落即可；既有工作单、证据与历史不受影响。
