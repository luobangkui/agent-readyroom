# 输入就绪驱动的四人协作 harness

## 目标与非目标

依据用户提供的协作方案，将「人物轮流接单」升级为「规划模型提交交付物依赖图，程序持续领取就绪任务」。让 A → D 在 B、C 尚未结束时推进；允许经过独立检查的接口版本提前触发实现。等待任务不绑定执行席位，真实模型轮次未结束前不假称释放资源。

保留四个人物、模型分配、历史会话、创建时人物选择、聊天/单人模式和旧委派工具。不增加代理或引入编排框架，不自动发布、推送、重试外部副作用。非 Git 项目沿用明确范围保护，不假称具备 worktree/容器隔离。本次不自动生成 worktree、合并提交或动态调整模型并发。

## 方案选择

1. 仅修改岗位提示词：不能消除人物占位和负责人逐次派单。
2. **现有工作单增加 v2 任务图、不可变成果、程序调度（采用）**：小接口，兼容现有服务和非 Git 项目。旧工作单不补造依赖。
3. 引入新工作流引擎和独立工作区：隔离能力更强，但增加运行、合并、迁移成本；以后作为执行器后端扩展。

## 四个角色

- boss / 目标规划与验收：定义目标、交付图、资源边界和验收，处理异常及最终交付。正常路径交给程序；简单任务仍可直接执行。
- tech / 契约与关键技术：版本化接口、架构、难点实现、高风险审查。不要求所有任务先等技术负责人结束。
- builder / 实现与集成：基于已固定输入实现、单测与集成。
- ops / 验证与资料支持：前置验收场景、测试准备、复现、文档/办公资料、独立验证。复杂代码安全/架构审查交 tech；作者不可自审。

角色是能力偏好，任务可声明多个 eligibleRoles，空闲合适成员领取；同一人物不永久占用一个等待中的任务。人物外观与岗位分离，角色 ID 和模型不变。

## 协议与状态

`office_submit_graph` 原子提交最多 24 个工作单，幂等 requestId，明确 key、task、eligibleRoles、scope、acceptance、dependsOn、requires、produces、reviewOf、resources、priority。任务间引用固定工作单 ID；循环、悬空依赖、重复生产版本、无法独立审查、资源过量、超出队列上限在落盘前拒绝。返工通过新 key + replaces 显式替代；依赖旧工作单的下游不暗中重绑，需要规划者明确安排受影响的修复/复核。

状态：waiting_input → ready → starting/running → completed；执行中可登记 checkpoint + requires，进入 suspending，只有收到模型轮次结束/中断确认才变为 suspended 并归还成员。输入就绪后重新领取和恢复。失败/过期进入需规划者决策，不自动重跑外部操作。

`office_publish` 发布本工作单声明的 name:version，保存小型文本文件内容快照和 SHA-256，附真实检查证据。`office_validate` 由另一成员检查该快照并登记通过；下游默认只消费 validated 版本。专门的契约检查任务可要求 published 版本。快照不得覆盖；v2 必须显式声明，已经消费 v1 的任务继续钉住 v1，不暗中升级。运行时提示下游使用快照而不是可能已变更的工作文件。独立验证证明协议和检查记录齐备，不保证模型证据真实性。

调度依据依赖、成果状态、适配成员、读写范围、资源配额。完成、发布、校验和恢复事件立即重新扫描就绪队列，优先高优先级/下游多的任务并给等待任务加权。模型名额只计算真实活动轮次；端口/数据库/浏览器/构建等通过声明资源键分别限流。资源是协作预约，不是操作系统强隔离。

每次领取增加 generation，每代均新建执行会话，挂起恢复带入明确检查点和固定输入，保留旧会话引用。每代使用新的 MCP capability token，旧 token/旧 turn 完成事件不能提交新工作结果。本机真实 Codex 检查发现 loaded thread/resume 不刷新 MCP 环境，因此新代次不复用已加载会话。工作单记录状态时间、等待原因、尝试/检查点和运行时间；不会把并行耗时相加冒充总体耗时。

## 模块与数据流

- `server/harness.js`：图校验、就绪条件、成果注册与快照、资源/优先级、状态指标。
- `server/missions.js`：持久化后派发、执行器生命周期、token fencing、恢复与停止、异常/最终规划唤醒。
- `server/collaboration.js`：复用 scope 和证据质量门；图的完成同样要求独立复核。
- `server/prompts.js` / `src/team.js`：新工具契约、职责与输入驱动协定。
- `src/collaboration-panel.js`：工作单状态、具体阻塞、角色领取、固定输入版本、资源与时间。

## 风险、兼容与回退

声明范围不是 OS 沙箱。共享目录读写交集继续串行；跨阶段并行依靠不可变契约快照和独立实现范围，不能假报 readPaths=[] 绕锁。未声明资源的真实外部争用无法自动发现。重启恢复保留快照和图，但不擅自续跑可能有副作用的工作；由用户继续后恢复未开始任务，已中断工作要明确重试授权。新协议只作用于新图，历史旧工作单沿用原调度。

运行超时只标记并请求中断，不在请求未确认时归还名额。自动重试次数为零；规划者可有限次数显式重试，并应核验外部操作幂等性。最终质量门保留结构化报告和作者之外的只读复核。

`office_retry` 也使用 requestId 去重，即使首次重试已经再次失败，同一请求也不会触发第二次执行。模型启动请求结果不明时保留名额，不假设模型没有启动；ZCode 保留已知执行 ID，以便取消和接收迟到事件。用户停止任务图时同样等待真实轮次结束，不能把中断请求成功当作全部停止。

## 验证

真实 MissionService + 可控执行器覆盖：A 提前完成触发 D；接口发布/独立验证后上游仍运行而下游启动；等待者不占成员；同成员多工作单；循环/无效图无副作用；资源互斥；挂起仅在真实结束后释放；旧 token/turn 拒绝；版本不可覆盖、消费者固定；保存失败不派发；停止与重启；质量失败与最终验收。实际浏览器验证等待原因、图输入版本和角色展示。无真实付费模型测试，不宣称实际提速比例。

### 运行时兼容决策

[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)支持恢复会话及配置覆盖，但本机 Codex 0.153.4 的真实调用显示：恢复**已加载**会话后，office MCP 仍使用旧环境。`scripts/check-harness-mcp.mjs` 通过实际 `mcpServer/tool/call` 到本机探针证实此行为（没有 `turn/start`），同时证实新会话使用新代次令牌。于是任务图每代使用新会话，而非假设 resume 会刷新令牌；原会话引用留在工作单 attempts 和人物 sessionHistory，恢复依据检查点和固定快照。普通聊天和旧版分工不强行换会话。
