# 按目录组织项目、目标和对话

## 目标与边界

左侧展示「项目 → 目标/对话」，选择已有本地目录创建项目。项目继承目录，新目标复用现有团队执行，新对话为单个助手会话，首次发送消息时才启动模型。保留已有目标、成员、消息和人物主题。跨浏览器共享项目与会话列表；当前选中项、主题与人物偏好仍为浏览器本地状态。本次不增加远程访问、项目文件删除、Git worktree 或多用户权限。

## 约束与选型

使用现有 Node HTTP/SSE、JSON 持久化和原生目录选择器，不引入框架或数据库。

1. 仅前端按 cwd 分组：改动小，但无法保存空项目，不适合创建后再开对话。
2. 后端新增 ProjectStore，目标/对话引用 projectId：支持空项目、真实目录校验、持久化和现有 SSE 同步，采用此方案。
3. 完整重写会话与数据库层：扩展性高，但会影响已验证的任务调度，当前无需采用。

## 实体与生命周期

- Project：id、name、cwd、createdAt。cwd 使用真实绝对目录去重，名称默认目录名。
- Mission：保留现有结构，增加 projectId、kind（goal/chat）。旧记录迁移为 goal，按 cwd 归组，缺失目录保留历史，发起新工作时重新验证。
- Chat：kind=chat、mode=chat，单个现有技术助手岗位；空对话为 idle，无模型请求。首次消息设置标题/上下文，再沿用 thread/start、turn/start、完成后继续原 thread 的机制。

## 模块与接口

- server/projects.js：目录规范化、去重、历史归组与 projects.json 原子保存。
- MissionService：绑定项目、创建空对话、普通目标启动、同目录调度与项目 SSE 快照。
- POST /api/projects：{cwd,name?} → {project}，沿用 Host/Origin/token 校验。
- POST /api/missions：{projectId,kind,prompt?,mode?,effort?,clientRequestId}；带 projectId 时工作目录由项目决定，拒绝不一致的 cwd。
- 前端：折叠项目树、项目首页、目录选择弹窗、项目下的新建入口。SSE 更新不自动跳离当前空项目/会话，不重建无变化的导航。

## 验证与回滚

覆盖目录重复/别名/无效路径、项目归属隔离、旧数据迁移和重启、空聊天无模型调用、首次发送及续聊、目标四岗位不变。使用真实浏览器验证项目树、新建流程、刷新、响应式布局。上线前备份原数据与改动文件，确认没有正在运行的任务后重启本机服务。项目记录先落盘，任务引用后保存；若中断产生未归组任务，下次启动按目录补齐。仅新增字段，原 missions.json 仍为数组，可用备份恢复。
