# 固定四人团队与模型路由

产品与项目负责人使用 GPT-5.6 Sol，负责目标、拆分、协调与业务验收；技术负责人使用 GPT-6 Astra，负责技术方案和审查；研发工程师使用 ZCode 的 GLM-5.3；运营与办公专员使用 ZCode 的 GLM-5.3-Flash。职位配置由 `src/team.js` 同时供界面与调度使用。

每个任务固定四位成员，未接任务的成员保持待命，按需启动会话。老板是只读协调者，只负责理解、委派、跟进和验收；技术负责人、研发工程师和运营与办公专员在普通执行任务中都可以创建和修改工作文件。两个 ZCode 员工使用免审批执行模式；共享目录仍由调度器做单写入者排队，防止同一文件互相覆盖。所有依赖都由调度器检查。

Codex 使用本机 App Server；ZCode 使用安装包自带的 stdio 会话服务，模型配置复用本机 ZCode 的选定提供方。密钥仅留在后端及其子进程环境，不进入浏览器、任务记录或源码。ZCode 的 office_* 协作工具通过每个成员独立的临时能力令牌连接本机 MCP 代理。

旧任务保留对话、结果与原会话引用。更换运行时或模型时，下次启动携带旧工作摘要，原会话归入该成员的 sessionHistory；不会把原模型的输出标记成新模型输出。

权限请求在工作台等待真实答复；暂停、停止、流式消息、工具事件与进度统一映射到现有任务事件。`plan` 模式仍是用户明确选择的只读例外。提供方断开只中断其实际运行的成员。模型缺失时报错，不默默换模型。精确网页地址优先走网页搜索，若地址被搜索安全策略拦截，则由 `office_fetch_url` 只读获取公开 HTML/文本。

协议参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。ZCode 协议以本机 0.16.5 安装包中的请求模式与运行验证为准。
